# 4KB RAM 单片机多任务方案说明

## 一、方案对比

### 1. 状态机/轮询方式（推荐，当前使用）

**优点：**
- 内存占用最小（几乎为0额外开销）
- 实时性好，无调度延迟
- 代码完全可控
- 适合资源受限的单片机

**缺点：**
- 需要手动管理状态
- 代码复杂度较高
- 需要良好的设计避免阻塞

**内存占用：** 几乎为0（仅模块内部状态变量）

**适用场景：** 所有功能都是非阻塞的状态机实现

---

### 2. 协程（Co-routine）

**优点：**
- 内存占用小（每个协程约40-80字节）
- 代码结构清晰，支持阻塞式编程
- FreeRTOS已支持

**缺点：**
- 需要启用FreeRTOS协程功能
- 功能相对受限（不能使用信号量、队列等）
- 需要修改FreeRTOS配置

**内存占用：** 约200-500字节（取决于协程数量）

**配置方法：**
```c
// 在 FreeRTOSConfig.h 中启用协程
#define configUSE_CO_ROUTINES         1
#define configMAX_CO_ROUTINE_PRIORITIES ( 2 )
```

**使用示例：**
```c
void vCoRoutine1( CoRoutineHandle_t xHandle, UBaseType_t uxIndex )
{
    crSTART( xHandle );
    for( ;; )
    {
        // 协程代码
        crDELAY( xHandle, 100 ); // 延迟100个tick
    }
    crEND();
}
```

---

### 3. 轻量级RTOS（RTX/FreeRTOS）

**优点：**
- 功能完整，支持优先级调度
- 代码结构清晰，易于维护
- 支持信号量、队列、互斥量等

**缺点：**
- 内存占用较大（每个任务需要栈空间）
- 对于4KB RAM可能过于占用资源

**内存占用：** 约1-2KB（取决于任务数量和栈大小）

**最小配置示例（FreeRTOS）：**
```c
// FreeRTOSConfig.h
#define configTOTAL_HEAP_SIZE         ( ( size_t ) ( 1 * 1024 ) )  // 1KB堆
#define configMINIMAL_STACK_SIZE       ( ( unsigned short ) 128 )  // 最小栈128字节
#define configMAX_PRIORITIES           ( 3 )                        // 3个优先级
```

**每个任务至少需要：**
- 栈空间：128-256字节
- 任务控制块：约80字节
- 总计：每个任务约200-350字节

**建议：** 4KB RAM下最多创建2-3个任务

---

### 4. 简单调度器（推荐作为优化方案）

**优点：**
- 介于状态机和RTOS之间
- 内存占用可控（约200-400字节）
- 可定制，适合特定需求
- 代码简单，易于理解

**缺点：**
- 需要自己实现和维护
- 不支持抢占式调度
- 不支持阻塞操作

**内存占用：** 约200-400字节（取决于任务数量）

**已实现：** 见 `task_scheduler.h` 和 `task_scheduler.c`

---

## 二、推荐方案：简单调度器

### 使用方法

#### 1. 在 main.c 中初始化

```c
#include "task_scheduler.h"

int main(void)
{
    Board_Init();
    
    // 初始化任务调度器
    TaskScheduler_Init();
    
    // 注册任务（按优先级从高到低）
    TaskScheduler_Register(key1_control, TASK_PRIORITY_HIGH, 10);      // 按键1检测，10ms间隔
    TaskScheduler_Register(key2_control, TASK_PRIORITY_HIGH, 10);      // 按键2检测，10ms间隔
    TaskScheduler_Register(RTC_Motor_TimerControl, TASK_PRIORITY_NORMAL, 100);  // RTC定时，100ms间隔
    TaskScheduler_Register(Audio_Update, TASK_PRIORITY_NORMAL, 0);     // 音频更新，每个循环执行
    TaskScheduler_Register(Battery_Update, TASK_PRIORITY_LOW, 500);    // 电池检测，500ms间隔
    TaskScheduler_Register(Fault_Update, TASK_PRIORITY_LOW, 1000);     // 异常检测，1秒间隔
    
    while (1)
    {
        // 运行任务调度器（替代原来的多个Update调用）
        TaskScheduler_Run();
    }
}
```

#### 2. 任务优先级说明

- **TASK_PRIORITY_CRITICAL**: 关键任务（如安全检测）
- **TASK_PRIORITY_HIGH**: 高优先级（如按键检测）
- **TASK_PRIORITY_NORMAL**: 普通优先级（如音频播放、RTC定时）
- **TASK_PRIORITY_LOW**: 低优先级（如电池检测、异常检测）
- **TASK_PRIORITY_IDLE**: 空闲任务

#### 3. 任务间隔设置

- **0**: 每个循环都执行（适合需要快速响应的任务）
- **>0**: 按指定间隔执行（节省CPU资源）

#### 4. 动态控制任务

```c
// 禁用某个任务
TaskScheduler_SetEnabled(task_id, 0);

// 使能某个任务
TaskScheduler_SetEnabled(task_id, 1);
```

## 三、内存优化建议

### 1. 减少全局变量
- 使用 `static` 限制作用域
- 使用局部变量替代全局变量

### 2. 优化数据结构
- 使用 `uint8_t` 替代 `int`（如果值范围允许）
- 使用位域（bit-field）压缩数据
- 使用联合体（union）共享内存

### 3. 减少缓冲区大小
- 音频缓冲区：64字节（已优化）
- 串口缓冲区：根据实际需求调整
- 避免大数组

### 4. 使用栈空间
- 临时数据使用局部变量（栈空间）
- 避免在栈上分配大数组

### 5. 内存池管理
- 如果使用动态内存，使用内存池替代malloc
- 固定大小的内存块，避免碎片

---

## 四、性能优化建议

### 1. 任务执行时间
- 每个任务函数应该快速执行（<1ms）
- 避免在任务中执行长时间操作
- 使用状态机实现长时间操作

### 2. 中断处理
- 中断处理函数应该尽可能短
- 在中断中只设置标志，在主循环中处理

### 3. 定时器使用
- 使用硬件定时器替代软件延时
- 利用定时器中断实现精确时间控制

---

## 五、总结

**对于4KB RAM的单片机，推荐使用：**

1. **首选：简单调度器**（已实现）
   - 内存占用：约200-400字节
   - 代码清晰，易于维护
   - 支持优先级和时间间隔控制

2. **备选：状态机/轮询**（当前方式）
   - 内存占用：几乎为0
   - 需要良好的代码组织

3. **不推荐：完整RTOS**
   - 内存占用过大（1-2KB）
   - 对于4KB RAM来说过于占用资源

4. **可选：协程**
   - 如果FreeRTOS已集成且需要阻塞式编程
   - 内存占用：200-500字节
